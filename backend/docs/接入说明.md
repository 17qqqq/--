# 后端接入说明（给算法模块的同学）

本文件说明：后端已经完成什么、你们需要实现什么、实现后怎么接进来。

## 一、分工边界

| 模块 | 归属 | 本仓库已提供 | 需要你实现 |
|---|---|---|---|
| 项目 / 模型登记 | 后端框架 | 完整 CRUD、启用模型 | — |
| 扰动参数配置 | 后端框架 | 开关存储 + GET/PUT 接口 | 扰动**算法**：`BasePerturbation` |
| 模型推理 | 算法同学 | 模型登记、启用接口 | `BaseInferenceBackend` |
| 鲁棒性指标统计 | 算法同学 | 报告/指标快照存储 | `BaseMetric` |
| 测试与缺陷检测 | 算法同学 | 调用契约 | `BaseDefectDetector` |
| 测试用例 / 测试计划 / 测试报告 | 本仓库 | 完整 CRUD + 数据库存储 | — |

## 二、扩展接口在哪

```
backend/app/interfaces/
├── __init__.py          # 统一导出
├── registry.py          # 注册表（四个接口共用）
├── inference.py         # BaseInferenceBackend + inference_backends
├── perturbation.py      # BasePerturbation + perturbations
├── metrics.py           # BaseMetric + metrics
└── defect.py            # BaseDefectDetector + defect_detectors
```

规则：

1. 算法实现放在你们自己的模块里，`from app.interfaces import ...` 拿到基类和注册表；
2. 用装饰器注册一个名字，**名字要和数据库/前端的约定一致**；
3. 本仓库不 import 任何具体算法类，只按名字取实现，双方互不依赖。

查看当前已经注册了哪些实现：

```
GET /api/v1/capabilities
→ {"inference": [], "perturbations": [], "metrics": [], "defect_detectors": []}
```

```python
    def predict(self, image):

        # 返回 (H, W) 的 0/1 掩码
        ...
```

### 2. 扰动算子 `perturbations`

```python
import numpy as np
from app.interfaces import BasePerturbation, perturbations


@perturbations.register("enable_noise")   # 名字 = PerturbationConfig 字段名
class GaussianNoise(BasePerturbation):
    key = "enable_noise"
    label = "高斯噪声"

    def apply(self, image, *, strength=100, params=None):
        sigma = (strength / 100) * 25
        noise = np.random.normal(0, sigma, image.shape)
        return np.clip(image + noise, 0, 255).astype(np.uint8)
```

三个已定义的开关：`enable_brightness`、`enable_contrast`、`enable_noise`。

### 3. 指标 `metrics`

```python
from app.interfaces import BaseMetric, metrics


@metrics.register("dice")
class Dice(BaseMetric):
    key = "dice"

    def compute(self, prediction, ground_truth):
        p = prediction.astype(bool)
        g = ground_truth.astype(bool)
        return float(2 * (p & g).sum() / (p.sum() + g.sum() + 1e-8))
```

`metric_name` 会原样存进 `report_snapshots.metric_name`。

### 4. 缺陷检测 `defect_detectors`

```python
@defect_detectors.register("vessel_break")
class VesselBreakDetector(BaseDefectDetector):
    def detect(self, image, prediction, ground_truth=None):
        return [{"type": "vessel_break", "score": 0.8, "bbox": [x1, y1, x2, y2]}]
```

返回 `list[dict]`，报告模块只依赖 `type/bbox/score/message` 这些通用键。

## 五、数据表

| 表 | 说明 |
|---|---|
| `projects` | 项目 |
| `ml_models` | 登记的模型（只存路径） |
| `perturbation_configs` | 每个项目一份扰动开关（含预留 `params` / `strength`） |
| `test_cases` | 测试用例（原图/掩码路径） |
| `test_plans` | 测试计划（状态、模型、扰动快照） |
| `test_plan_cases` | 计划-用例多对多 |
| `reports` | 报告（摘要、汇总指标、状态） |
| `report_snapshots` | 指标明细（扰动类型 × 指标 × 值） |

建表方式：启动时 `Base.metadata.create_all`。**新增字段不会自动迁移**，
开发阶段删掉 `test_platform.db` 重启即可。

## 六、提交报告的两种方式

1. 算法/执行模块算完后直接调 `POST /api/v1/reports`：

```json
{
  "project_id": 1,
  "test_plan_id": 3,
  "title": "噪声扰动评估",
  "summary": "Dice 平均下降 0.12",
  "metrics": {"dice": {"baseline": 0.93, "noise": 0.81}},
  "snapshots": [
    {"perturbation_type": "noise", "metric_name": "dice",
     "metric_value": 0.81, "baseline_value": 0.93, "case_id": 5}
  ]
}
```

2. 在 Python 里直接调用 `ReportService(db).create(payload)`，适合执行引擎内部使用。

`POST /reports/generate` 目前返回 501，等推理/扰动/指标实现接入后，
把 `ReportService.generate` 里的占位替换成执行链路即可。
